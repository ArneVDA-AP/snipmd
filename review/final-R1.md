## Checked and sound

- **Atomic writes** (guardrail 1). Notes and `session.json` go through `atomic_write`: a temp file in the same folder, `sync_all`, then rename. The temp file is removed on error, and a read-only target is refused.
- **New images** (guardrail 2). `create_unique` uses `create_new` and retries on `AlreadyExists`. The name follows the SPEC format. Raw IPC body for paste.
- **Moves** (guardrail 3). `move_dir` renames first, then copies file by file and removes each source only after its copy has synced. `copy_dir` never overwrites, and an interrupted run can finish.
- **Cleanup** (guardrail 4, SPEC §6.5). It runs only from `.setup()` on its own thread and only lists valid tab-id folders under `scratch`. Folders and items count by their newest mtime. A tab with a file path keeps everything. References are decoded and case folded. An unreadable session, or one with no tabs, deletes nothing.
- **Failure isolation** (guardrail 5). Write failures stay per tab. `flushDirty` uses non-rejecting `writeTab`, and the session is written first. Session errors use a lasting keyed bar.
- **Stamped writes** (SPEC §6.1). Every note write carries a stamp. Rust refuses a write after a change or deletion made outside SnipMD. Clean tabs reload with the middle of the doc replaced. Dirty tabs get the conflict bar, and autosave pauses for them. A gone file gives "Save again". Restored dirty tabs are checked at start.
- **Closed tabs** (SPEC §7). Entries keep their editor state. Entries with unwritten edits outlive the 20-entry and 14-day limits. A close that could not write gives a warning bar with Restore. Ctrl+Shift+T works after a restart.
- **First save and Save As** (SPEC §6.2, §6.4). The note is written before images move and links are rewritten. The rewrite is one transaction and only touches Image URLs that start with the exact prefix. Save As keeps the original note and folder. A same-path Save As falls back to a plain save.
- **Security** (SPEC §8, guardrails 7-9). Every Rust command that takes a path checks it against the AllowedSet, using one lexical walk that refuses trailing dots and spaces and folds case. `resolve_image` refuses absolute, drive, UNC, `..` and `:` paths and percent-decodes first. The asset scope is granted per image file. The CSP has no inline scripts and `connect-src` is limited to IPC. There is no fs plugin. The capabilities are window-only.
- **Read mode**. DOMPurify plus a hook that drops non-web image and link URLs. App-resolved images get their `src` only after sanitizing. Clicks on links go to `open_link`, which accepts only http(s) and mailto and parses with `Url`. The `on_navigation` guard allows only the app's own origin. wry denies new-window requests when no handler is set (`webview2/mod.rs` `args.SetHandled(true)`), so a middle-click or `target=_blank` cannot open a window.
- **No HTML from user text**. File names, paths and errors go into the DOM through `textContent` only. The only `innerHTML` is a constant skeleton.
- **Commands off the main thread**. Every disk-touching command is `#[tauri::command(async)]` or `async fn`. A release-mode panic (`panic = "abort"`) has no reachable path in the commands I read.
- **Keyboard** (SPEC §10). The table is wired with AZERTY digits by `e.code`. AltGr is not swallowed. A held key acts once except for tab moves. F6 cycles regions. The tab strip has roving focus. Esc dismisses non-sticky bars.
- **Paste rules** (SPEC §6.3). Text wins. Ctrl+Shift+V never saves an image. A paste is bound to its tab id through `applyToTab`.
- **Single instance**. Relative paths resolve against the caller's cwd. An already open file activates its tab.

Verdict: not ready for v1. There is no blocker, but three majors are open: M1 (a screenshot that is still saving is lost on Alt+F4 or Ctrl+W), M2 (a drop in read mode lands in a hidden note) and M3 (F5, Ctrl+R and right-click Refresh reload the app). PLAN Goal item 6 needs them closed.

## Resolution (main session, branch claude/phase-6d)
- M1 fixed: every paste and drop registers its save in `editor/registry.ts` (`trackImageSave`) until its links have landed. `flushDirty` (window close, blur) waits for them before writing, inside the existing 3 s close limit; `closeTab` keeps an empty untitled tab while a save into it runs, so the link lands in the closed entry and Restore brings it back. Tests in registry, saving and tabs.
- M2 fixed: a drop goes to the active tab, not to the tab the hidden editor view last held; a tab in read mode is rendered again with its new images. Test in drop.
- M3 fixed: F3, F5, F7, Ctrl+R, Ctrl+P, Ctrl+J, Ctrl+U, Alt+Left/Right and the browser keys do nothing; the browser context menu (Back, Reload, Print) only opens over the note, inputs and selected read-mode text, where it offers spelling, cut, copy and paste. Tests in app. Windows test: F5 and right-click outside the text do nothing in the real window.
- Fixed minors: an unreadable `session.json` is kept aside as `session.unreadable-<time>.json` instead of being overwritten; a paste mid-note leaves the cursor on an empty line before the next text; the session is written right after a save; "Open disk version" and "(closed)" copies open next to their tab; the first-save name gets `.md` when typed without it, and a `#` comment in a code block is not taken as the heading.
- Left: read mode is not re-rendered after a silent reload (Ctrl+E twice shows it; a reload of a tab being read is rare); a failed image move after a first save is retried from its bar only; `write_markdown_file` can reach the app data folder (defence in depth only: the frontend never sends such a path, and a lexical case-folding check belongs with the allowed set, not in one command); the late-bound hooks in external.ts, tabs.ts and registry.ts stay until a module is reworked.

# Repo health review R1: everything around the code

Scope: `main` at 6988b9d (Merge PR #20). Every read was pinned to that commit with `git archive 6988b9d`, because the checkout moved from 1281c1b to 172cbfc to 6988b9d while this review ran. Source code (`src/`, `src-tauri/src/`) was read only to check doc claims.

## Verdict

The code is manageable for a human maintainer. The repository around it is not yet: it carries the typical overhead of an AI-built project. About 80% of the tracked bytes are screenshots that served as review evidence (4.03 MB of 5.05 MB). The process records add up to about as much as the code: reviews, verifier reports, run args, the plan's history and a vendored agent framework come to about 450 KB, against 320 KB of TypeScript, Rust and CSS including tests. A maintainer needs about a dozen files: README, SPEC, ARCHITECTURE, CONTRIBUTING, SECURITY, CHANGELOG, RELEASE-WIN11, the workflows, `tools/measure`, `fixtures/evil.md` and `docs/images`. The rest is history or agent tooling. The truth problems sit in PLAN.md and CLAUDE.md, the two files CLAUDE.md names as ground truth. SPEC, README and SECURITY agree with the code on every point checked: data folder, keys, CSP, async commands and the named helpers. CI basics are sound and there is no `pull_request_target`. The release path has two real faults: a write token is present in the job that runs dependency code, and the release gates only check the last command's exit code. Nothing here needs a history rewrite. Moving the residue off `main` and cutting two files is about a day of work.

## Resolution (main session)
- M1 fixed: find from read mode opens the panel after the editor's focus frame (browser probe: typing lands in the replace field, the note is unchanged).
- M2 fixed: a held Delete or Enter in the strip acts once; keys in the strip keep focus there, so a close never hands keys to the next note (browser probe: held Delete closed one tab, the next note intact). A mouse press on a tab no longer takes focus; Enter opens the tab and moves focus into it.
- M3 fixed: SPEC §4, §5 and §10 describe the reading chip, the empty-tab hint, Mica, F6, the strip keys, Esc and find from read mode.
- Fixed minors: Ctrl+H from the find field; focus kept when tabs reorder; selection-match highlight removed; search match colours are tokens checked for AA; `returnFocus` passed at mount, and any bar that goes while holding focus returns it; F6 ignores repeats; `index.html` paints the theme background before the CSS loads; dead export and dead CSS removed.
- Left as they are: no focus ring on the read pane (it is a scroll area; a frame around the page looked like an error); a code block inside a quote gets the quote style only; Ctrl+F from the strip or a bar in edit mode is CodeMirror's and works only in the note.
- To the Windows test: Mica really applied (set_effects reports dispatch, not effect), no desktop showing through on a cold start and a resize on Windows 10 and 11, bar text readable over Mica on a light and a dark wallpaper.

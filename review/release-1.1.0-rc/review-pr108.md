## Is the untested FOUT path certain enough?

Yes. A forced-FOUT run is not needed before merge.
- GitHub's contexts reference, steps context: "`steps.<step_id>.outcome`: The result of a completed step before `continue-on-error` is applied. ... When a `continue-on-error` step fails, the `outcome` is `failure`, but the final `conclusion` is `success`."
- The exit-codes page: a nonzero exit gives check run status "failure", and "The check run and check suite both get a `failure` status."
- The retest step's script does exit 1 on a FOUT under this shell. Observed in run 42548388376: `##[error]Process completed with exit code 1.`, with the step's conclusion `success`, which is exactly the documented continue-on-error case.
- Run 42552383903 shows that the `if:` expression is valid and skips the step on a pass.

What remains unexercised is only the bash step's `exit 1` in a job on windows-latest. That is the documented behaviour of every failing `run:` step. A forced-FOUT run is still worth doing once, for example with a temporary bad expectation on a scratch branch, but it does not gate this merge.

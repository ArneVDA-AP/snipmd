## Checked and holding

- Paths outside scratch: `DirEntry::metadata` does not follow links, so a symlinked or junctioned tab folder is not a directory and is skipped. Names that fail `valid_tab_id` and loose root files are not listed. Non-UTF-8 item names are kept.
- Session handling: no session.json, a read error or JSON that does not parse all mean no cleanup. A file path makes a tab `None`, so all its items are kept. A duplicated id concatenates its texts, and once `None` it stays `None`. A future mtime counts as young.
- A tab in conflict is not written on close. Its conflict flag stays, and restore calls `resolveConflict`, after which the watch raises the bar again (probe P5: `inConflict: true`, bar shown).
- Closed entries keep their text in the session, and a write that ends after the close marks the entry saved.
- The restore bar is built with DOM APIs and has key `closed`, position bottom and 8 s timeout.
- §10 keys: digits match on `e.code` (AZERTY Ctrl+1). No key overlaps the CodeMirror Windows keymap (the `Ctrl-t/e/o/n` bindings are the mac-only emacs set). Ctrl+F, Ctrl+H, Ctrl+V and Ctrl+Shift+V pass through.

## Checked and sound

- **#79 itself.** `Expected::Absent` deserializes from `"absent"` (untagged enum). `note::write` compares `stamp(path)` with `None` and refuses with the stamp it finds. `matches()` in `external.ts` treats `'absent'` as "no file expected", so the watch neither raises nor clears falsely. `parseDisk` keeps `'absent'` across a restart. A refused Save again raises the changed bar. A missing folder ends up as a write failure (stat gives NotFound, the atomic write fails). A closed tab with `disk: 'absent'` that is flushed on blur cannot replace a note saved at that path meanwhile. The stat-then-rename window is #25.
- **Atomic writes, images and moves** (guardrails 1 to 3). These are unchanged since v1.0.0. `atomic_write`, `create_unique` and `move_dir`/`copy_dir` read as before.
- **Session** (guardrail 6, SPEC §6.5, §7). Settings are parsed per key, with defaults for an older file. A session Rust cannot read is set aside and never overwritten, and `startSessionWrites` is skipped when it could not be kept aside. Cleanup returns early on a session with no tabs.
- **Read mode** (guardrails 7, 9, SPEC §8). The new code, task and own-image markers carry a per-render UUID token. A note's copy of `data-code`, `data-task` or `data-own` is stripped, or gets no URL. Probe `zz_xss`: `onerror`, `javascript:` (also padded and upper case), `svg`/`math` script, `iframe`/`object`, `ontoggle`, `class="infobar"`, `data-tauri-drag-region`, links to `asset.localhost`/`ipc.localhost`/`tauri.localhost`, and a code fence that tries to close `</code>` were all neutralized, and no link reached `openLink`. Highlighting builds spans with `textContent` only. There is no new `innerHTML`, `style` attribute or injected `<style>` (grep).
- **Task clicks.** Probe `zz_tasks`, 12 edge cases: an empty `- [ ]`, a tab after the marker, a lazy line, a list after an HTML block, a quote inside a list, a heading or table cell with `[ ]`, ordered `1.` and `2)`, indented code, and `[ ]` inside item text. Every click flipped the matching line or was refused with the bar. None flipped a different task.
- **Editor guardrails 10 to 12.** Block widgets still come only from `imageWidgetField` (a StateField). Task clicks, drops, pastes and link rewrites go through `applyToTab` with the tab id. A drop on a read-mode tab now targets `getActiveTab()` (v1 M2 fixed). Image saves are tracked per tab and awaited by close and flush (v1 M1 fixed).
- **UX guardrail 13.** There is no `alert`, `confirm`, `prompt` or `<dialog>` (grep). The command menu, the task mismatch and the copy failure all go through the info bar with keyed `:<tab id>` keys. F5, Ctrl+R, Ctrl+P, F7, Ctrl+J/U and the browser Back/Refresh keys are suppressed, and the page context menu is limited to text (v1 M3 fixed, `app.ts:157-179`).
- **SPEC §9 per keystroke.** `onDocChange` only marks dirty and schedules. Snip never reacts to edits. List renumbering runs only for line-changing user edits and iterates only the changed range. The full image-decoration rebuild per edit is #26. The find count is m1 above.
- **Startup.** Every code language and Snip's sprites are dynamic imports. The built `index.html` preloads none of them. The startup chunk grew from 397 KB to 437 KB. I could not measure time here, so the < 150 ms budget needs the Windows measurement.
- **Rust surface.** No new command. Capabilities are unchanged apart from the description. There is still no fs plugin, and the dialog and opener plugins have no page permissions.

Verdict: no blocker. One major is open: M1, where one tab per note (#79, SPEC §6.4, §11) breaks through a concurrent open or a `.\`/`..\` path from the command line. It does not lose data silently, because stamped writes turn it into a conflict bar. But it is the rule this release's headline fix states. Whether it holds 1.1.0 back is the coordinator's call.

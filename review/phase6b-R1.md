## Suggested fixes for the majors

- M1: use `commonmarkLanguage` in `markdownSupport`. That restores the 6a node shapes, the bundle stays at 396.86 kB, and the repro test passes. Alternatively, keep GFM and take the `URL` child after the `](` LinkMark in `imageLink` and `prefixChanges`. Either way, add a test with a URL in the alt text.
- M2: check AppActivate. `if (-not $shell.AppActivate($p.Id)) { throw 'SnipMD did not take focus' }`. Then confirm the foreground window belongs to `$p.Id` (GetForegroundWindow/GetWindowThreadProcessId) right before each SendKeys.
- M3: start each run with a fixture `.md` argument and a seeded `session.json`. Report the first run as cold and the median as warm. Give the WebView2 data folder its own location too (for example `WEBVIEW2_USER_DATA_FOLDER`, or let `SNIPMD_DATA_DIR` set `data_directory`).

Verdict: not ready to merge. M1 is a correctness regression in edit-mode image display and in the Save As link rewrite. M2 and M3 must be fixed before the measuring script's numbers are recorded as SPEC §9 results.

## Resolution (main session)
- M1 fixed by keeping GFM (strikethrough, tables and task lists stay styled) and finding an image's target as the URL after its `(` mark (`src/editor/imageUrl.ts`), used by the image widget and the link rewrite; tests with URLs and mail addresses in alt text.
- M2 fixed: keys are only sent after the foreground window is checked to be SnipMD's; otherwise the script stops.
- M3 fixed: start is measured as SnipMD is started in use, with a note as argument and the session of the run before; the first run is reported alone, later runs as a median. The WebView2 profile is the user's own on purpose (normal use has a warm profile); documented.
- Fixed minors: one write per log line; a non-absolute `SNIPMD_DATA_DIR` is an error, never a fallback to the real data; the page follows pastes only while tracing is on, a paste slower than 10 s is logged as 10 s, and the paste mark waits for the frame after decode; a failed read-mode load shows an error; the memory figure is documented as private bytes; GDI objects disposed and the clipboard overwrite documented; the test restores `decode`.
- Left: read-pane scroll captured as 0 when switching during the first chunk load (one time, and only before the chunk is cached); HTML tag completion and auto-close tags are gone with the HTML parser, recorded in PLAN Decisions.

# Phase 5 review R1

Scope: phase 5 changes on `claude/phase-5` (foundation 9401e13, build 60035bd: `core/src/cleanup.rs`, `src-tauri/src/lib.rs` startup cleanup, `src/closedTabs.ts`, `src/app.ts`, closed-tabs list in `src/tabs.ts`, `clearTabInfo`). I checked them against SPEC §6.5, §7, §10, §11 and CLAUDE.md guardrails 1-6, 12, 13 and the code conventions.

What I ran: `npx vitest run` (14 files, 153 tests pass), plus a throwaway probe crate against `snipmd-core::cleanup` (since removed).

What holds: cleanup runs once per process, on a spawned thread, and only after session.json parsed. Top-level symlinks and junctions are skipped. Future mtimes count as young. Closed tabs are in the live map. Every close path goes through `closeTabWithRestore`. The restore bar is built with DOM APIs. Ctrl+1..9 match on `e.code`. AltGr (Ctrl+Alt) is ignored. No CodeMirror default key collides with the §10 keys handled here. A write that ends after the close lands on the closed entry through `findTab`. A restored tab gets `resolveConflict`, and the watch compares it with its file again.

## Verdict

One human can maintain this. It is not over-engineered in the usual AI way. There are no factories, no DI container, no plugin points, no config nobody uses and no wrapper classes around libraries. About 4,300 production lines (2,803 TS, 1,489 Rust) cover tabs, an autosaving session, closed-tab restore, external-change conflicts, a first-save form, paste and drop with per-note image folders, sanitized read mode, a path allow-list and startup cleanup. For that scope the size is about right, maybe a little lean. The excess is defensive accretion, not abstraction. I estimate 10 to 15 percent of the cost is in the close, restore and save flows. Many review rounds left special cases there, plus a web of late-bound hooks and per-tab maps that a maintainer has to keep in their head. Roughly 50 comments cite plan IDs (T5, R8, C3, D7, "Phase 4") that point at PLAN.md contracts which are now out of date. The model behind "a closed tab is a tab without a view" makes every call site choose between `getTab` and `findTab`. One call site already chose wrong, and I reproduced the result: a screenshot pasted just before Ctrl+W on a disk note is saved to the scratch folder and linked as `untitled.assets/...` inside the disk note. Fixing the model, not only that line, is the most valuable simplification. Removable code is modest: about 100 to 150 production lines and about 150 test lines. The real gain is fewer rules to remember, not fewer lines.

## What is good and should stay

- The Rust core crate. Pure, Tauri-free functions with 57 tests on real temp folders. One lexical path walk (`components`) used by both the link resolver and the allow-list, atomic writes that keep symlinks, and a `move_dir` that can resume. This is the part of the code with the highest stakes and the best tests.
- The security model is coherent and small. Sanitize first, then set trusted image URLs on the clean DOM (render.ts:69-76); URLs are checked with the same parser the webview uses (paths.ts:28-46, links.rs); `AllowedSet` in one place; the asset scope gets single files.
- `ImageHome` (lib.rs:164-230) decides once per command whether a tab is a note or untitled. A good small abstraction with three users.
- `ipc.ts` really is thin. `app.ts` is the only wiring point, and the import graph has no cycles.
- The save queue in `writeTab` (saving.ts:42-68) is short and handles a real need (no overlapping writes, saves merge).
- Few dependencies, no framework, lazy-loaded read mode. The TS suite runs in about 12 s.

## Defects

### D1. WebView2 autofill popup ("Saved info") over the find/replace fields (observed)
- Shot: `findings/ui/windows/100/find-dark.png`.
- Repro: run `tools\measure\shots.ps1` (or: open a note, Ctrl+H, type `scope`, Esc). Start SnipMD again, Ctrl+H,
  type `s`.
- Expected: no browser popup.
- Actual: a "Saved info" dropdown with the earlier value `scope` opens under the field and covers the note.
- Note: the value survives between runs with different `SNIPMD_DATA_DIR` folders, so it is stored in the WebView2
  profile (`%LOCALAPPDATA%\com.snipmd.desktop\EBWebView`), not in the SnipMD data folder. Search text from one data
  folder shows up in another (inferred from the light run, which had no popup, followed by the dark run, which did).
  Likely fix (inferred): `autocomplete="off"` on the panel inputs, or turn off general autofill in the WebView2
  settings.

### Note N1. Ctrl+H with an empty find field puts the cursor in the replace field (observed, by design)
- `src/editor/search.ts:7` says this is intended. With an empty find field, typing after Ctrl+H goes into Replace,
  so `find-*.png` shows `scope` in Replace and no match highlighted. VS Code focuses Find on Ctrl+H. The dev session
  decides; at least `shots.ps1` should type into Find so the shot shows a match.

### Brief correction
- The data folder of the installed app is `%APPDATA%\com.snipmd.desktop` (Tauri identifier `com.snipmd.desktop`),
  not `%APPDATA%\snip-md` as the brief and the `lib.rs:150` comment say. The backup was made of the real folder.
